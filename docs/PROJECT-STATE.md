- [x] Phase 7.2 Backend Database Environment Resolution & Recovery Error Observability (2026-11-15): Diagnosed and resolved the root cause of the "Account security service is unavailable" (HTTP 503) error on `/admin/verify-recovery`. Root cause: `backend/src/server.js` and `backend/src/db.js` only attempted to load `.env` from `process.cwd()`. In this monorepo layout, the root folder has no `.env` (it only has `.env.example`), so starting the backend from the root directory or without an explicit current directory left `process.env.DATABASE_URL` uninitialized, causing Prisma queries to fail and trigger the catch block in `POST /api/auth/recovery-email/confirm`. Furthermore, error logging was absent in the catch block, and `PAYLOAD_MISSING` errors fell through to 503 instead of 400. Fixes: added robust relative path `.env` resolution in `backend/src/db.js` and `backend/src/server.js` (`resolve(__dirname, '../.env')`), added explicit safe error logging to `authRecovery.js` catch blocks, classified missing payloads as invalid tokens (HTTP 400), and started the backend and Vite dev servers cleanly. Verified: live `/api/health/db` endpoint returns HTTP 200 with `database: connected`, and end-to-end token creation, proxy confirmation (HTTP 200), replay defense (HTTP 400), and password reset flows pass.
